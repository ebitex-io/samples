# Northwind Coffee — MVC

A small coffee roaster's shop, rendered entirely by its own server.

This is the third build of one site. [`northwind-coffee`](../northwind-coffee) is a static Vite SPA,
[`northwind-coffee-ssr`](../northwind-coffee-ssr) renders on a Next.js server and then hydrates, and
this one is ASP.NET Core MVC with Razor views and **no client-side framework at all**. Every page is
finished HTML when it leaves the server, and nothing in the browser ever takes it over. It talks to
Content through [`Ebitex.Content.Delivery`](https://www.nuget.org/packages/Ebitex.Content.Delivery),
installed from nuget.org exactly as you would install it.

## What it teaches

| Area | Where to look |
|---|---|
| One request per page, and its four answers | `Controllers/PageController.cs` |
| Renderer-per-Template, found by external id | `Rendering/PresentationHtmlHelperExtensions.cs`, `Views/Presentations/` |
| RichText, and markdown pinned to the delivered dialect | `Rendering/RichTextHtmlHelperExtensions.cs`, `Rendering/MarkdownRenderer.cs` |
| Personalization decided on the server | `Rendering/RequestContext.cs`, `Controllers/BuyerTypeController.cs` |
| Streams, facets and paging without JavaScript | `Content/Catalogue.cs`, `Views/Presentations/coffee-index.cshtml` |
| Live preview for a site that never hydrates | `Preview/PreviewSessionMiddleware.cs` |
| Sitemap XML, index and shards | `Controllers/SitemapController.cs` |
| Structured data from the Contract, not the Template | `Rendering/PageMetadata.cs` |

## What differs from the SSR sample

The two are the same site and the same content. Everything not listed here is a port.

| | `northwind-coffee-ssr` | this sample |
|---|---|---|
| Talks to the API through | `@ebitex/content-sdk` | `Ebitex.Content.Delivery`, from nuget.org |
| Renders with | React server components, then hydrates | Razor, and nothing runs in the browser |
| Renderer registration | a static map of components | a partial per Template, found by name |
| Markdown | `react-markdown` + GFM | Markdig, restricted to the delivery dialect |
| Catalogue filters | a client component and a BFF route | links and a `GET` form; the page itself is the endpoint |
| Buyer switcher | `router.refresh()` | `<form method="post">`, then a redirect |
| Freshness | two caches to clear on publish | no cache: the package holds none, and neither does this app |
| Live preview | the browser bridge (`postMessage`) | a preview session, exchanged server-side |
| Types | generated by `content-sdk-codegen` | the package's records; your Contract's fields as `JsonElement` |

**What you give up by not hydrating:** click-to-edit pins in Composer. Live preview still works — you
type in Composer and the framed page reloads with your draft — but there is no in-page pin to click,
because there is no client code to draw one. That is the trade this sample exists to show, not a
limitation to work around.

## Prerequisites

- .NET 10 SDK
- An ebitex organization you control. A free one is enough; live preview additionally needs a
  server-side delivery key with **Allow draft preview**, which any tier can mint.

## 1. Seed the content

Import `../northwind-coffee/seed/final.zip` into your own organization (Content › Configure ›
Transfer › Import). It carries the whole content model and every page this site renders — the same
bundle both other Northwind samples use, unchanged.

## 2. Configure

Nothing is committed but the setting names. Use user-secrets, so a key never reaches a file that
could be committed:

    dotnet user-secrets set "Content:DeliveryKey" "frm_live_..."
    dotnet user-secrets set "Content:SiteId"      "00000000-0000-0000-0000-000000000000"

| Setting | Where to get it |
|---|---|
| `Content:DeliveryKey` | Content › Configure › Delivery, in your own organization. **Server-side**, not browser-safe: a server sends no `Origin`, so a browser-safe key is refused. |
| `Content:SiteId` | The site's root node id, in Composer's address bar. Required: the API cannot infer your site from a server's request. |
| `Content:ApiBaseUrl` | `https://api.ebitex.io`, or your own host. The **origin** only — the client appends `/content/delivery/v1`. |
| `Content:FrameAncestors` | Composer's origin, for `Content-Security-Policy`. Defaults to `https://content.ebitex.io`. |
| `Content:Origin` | This site's own origin, for absolute sitemap URLs. |
| `Content:FormsOrgSlug` | Your organization's slug, if you want the contact form to load. |

Start it with none of these set and the site explains what is missing rather than failing — which is
also how it builds in CI, with no credentials at all.

## 3. Run

    dotnet run

Then open <http://localhost:5181>.

## Live preview

This site never hydrates, so Composer's browser bridge has no tree to hand a draft to. It uses a
**preview session** instead: Composer frames a URL carrying a one-time token, `PreviewSessionMiddleware`
spends it once for a session secret, keeps that in a `Partitioned` cookie, and sends it on the page
read. To try it:

1. In Composer, Settings › Sites › Live preview, mark this site's host **Server**.
2. Give your delivery key **Allow draft preview**.
3. Open a page in Composer's preview and type. The frame reloads with your draft.

Only the page being previewed answers as a draft; every other path answers published. Close the layer
and the session ends, the cookie is cleared, and the published page renders.

## Regenerating the stylesheet

`wwwroot/css/site.css` is committed, so running this sample needs `dotnet run` and nothing else. It is
Tailwind output, and if you edit a view you can rebuild it — optional, and the only reason there is a
`package.json` here at all:

    npm install
    npm run css

## Structure

```
Controllers/        the catch-all page route, the sitemap, the buyer switcher
Content/            configuration, chrome, the catalogue query, formatting
Preview/            the preview-session middleware
Rendering/          presentation dispatch, RichText, markdown, metadata, images
Views/Presentations/ one partial per Template external id
Views/Shared/       layout, header, footer, and the 404 / error / not-configured pages
Styles/             the Tailwind source for wwwroot/css/site.css
tests/              the sample's own pure parts
```
